- (constraint) INHERITED from PRD NFR-2 (binding, not re-decided): the simulation is deterministic and fixed-timestep, with all combat timing expressed in simulation ticks rather than wall-clock or rendered frames.
- (constraint) INHERITED from PRD NFR-5.3 (binding): the renderer is a pure view layer over an independent TypeScript simulation. Working choice PixiJS. An engine holding simulation state forecloses replay validation.
- (constraint) INHERITED from PRD FR-15 (binding): server issues the run seed and records start time; client posts signed checkpoints; server computes the reward itself and never trusts client-claimed loot; balances are never client-written; awards land in an append-only ledger keyed by run id.
- (constraint) INHERITED from PRD FR-16 (binding): cosmetic entitlements are server records granted only by verified payment; what other players see is served from the server's record, never relayed from the wearing client.
- (constraint) INHERITED from PRD NFR-1 (binding): tuning values live server-side and change without a redeploy; content is additive and removable without breaking saved progress; persistent state migrates rather than resets; per-run telemetry exists from the first playable build.
- (constraint) INHERITED from PRD NFR-5.1 (binding): stateless serverless plus managed Postgres, no always-on process, no fixed monthly infrastructure spend at low scale. This is what rejected full server simulation.
- (constraint) INHERITED from PRD FR-9.5/9.6 (binding): combat timing values are identical on PC and phone. No per-device windows, because v2 leaderboards and v3 PvP must compare the same game.
- (decision) PARADIGM: FUNCTIONAL CORE, IMPERATIVE SHELL. The simulation is a pure reducer step(state, inputs) -> state with no I/O, no clock, no internal randomness; everything else - renderer, network, storage, input devices - is shell. Chosen because it is the one paradigm that makes NFR-2's three dependents (device timing parity, replay validation, tick-range hitbox authoring) fall out for free rather than being separately engineered. Alternatives weighed: layered (too weak - permits I/O anywhere), ECS (orthogonal; can live INSIDE the core later without changing the spine), full hexagonal (more ceremony than a solo browser game needs).
- (decision) AD: SIM IS A PURE REDUCER. step(state, inputs, tick) -> state. It returns new state and never mutates the world. Binds all game logic. Prevents the divergence where one unit reads the clock or fetches and another does not, making runs irreproducible.
- (decision) AD: TICKS ARE THE ONLY UNIT OF TIME. TICK_HZ 60; every duration in the sim and in tuning data is an integer tick count. Prevents millisecond drift and per-device timing.
- (decision) AD: BANNED APIS IN THE CORE - Math.random, Date.now, performance.now, new Date, transcendental Math functions, DOM globals, fetch. Already enforced by an ESLint override on src/sim. Prevents silent determinism drift, which surfaces as false-positive replay rejections that eat real players' loot.
- (decision) AD: RANDOMNESS DERIVES FROM A SERVER-ISSUED SEED VIA NAMED STREAMS - one independent stream per concern (encounters, chests, traps, modifier). Prevents the failure where changing how many chests a run rolls shifts every subsequent trap position and invalidates every stored replay.
- (decision) AD: DEPENDENCY DIRECTION IS ONE-WAY - config <- sim <- render <- app. sim imports only config and the standard library; render may import sim; app may import both; nothing imports app. Prevents circular dependencies and, more importantly, prevents renderer or framework state leaking into the core.
- (decision) AD: INPUTS ARE ABSTRACT TICK-STAMPED INTENTS, not device events. The shell translates keyboard and touch into the same intent set before the core sees anything. Prevents device-specific behaviour reaching the sim and is what makes FR-9.5 universal timing and device-agnostic replay logs possible at all.
- (decision) AD: SERVER LOGIC LIVES IN NEXT ROUTE HANDLERS ON VERCEL. Supabase Edge Functions are NOT used in v1. Rationale: the sim must run server-side for replay validation, and Route Handlers are Node so they import the identical TypeScript module the browser runs; Edge Functions are Deno and would mean a second deployment target and a second runtime to keep deterministic. One language, one module, one deploy.
- (decision) AD: POSTGRES OWNS ATOMICITY. Every economy mutation is a single SECURITY DEFINER Postgres function called via RPC, never a sequence of PostgREST calls, because a serverless function cannot hold a transaction across multiple round trips. Prevents partial awards and lost-update races.
- (decision) AD: BALANCES ARE DERIVED, NEVER UPDATED. An append-only ledger of deltas keyed by (user, run_id, reason) with a unique constraint on run_id per award type; balance is a sum. Prevents double-award from a retried request - a duplicate becomes a constraint violation rather than silent theft - and gives every unit of currency a traceable origin.
- (decision) AD: RLS IS DENY-ALL ON ECONOMY TABLES. No client role may insert or update ledger, balances, entitlements, or run records. Reads are scoped to the owning user. All writes go through SECURITY DEFINER functions or the service role, server-side only. Prevents the client-trust creep that a single permissive policy would open.
- (decision) AD: TUNING IS SERVER-OWNED VERSIONED DATA, not code constants. The client fetches a tuning document with a version id; src/config/tuning.ts is the fallback and the schema. Every run record stores the tuning version it was played under, so a replay is re-simulated against the numbers that were live at the time. Prevents a tuning change silently invalidating the stored replay corpus - the exact failure that would make FR-15.7 worthless.
- (decision) AD: THE SIM IS ISOMORPHIC. The same module runs unmodified in the browser and in a Route Handler. No Node-only and no browser-only APIs in the core. Prevents play and validation from drifting apart, which is the one bug class that cannot be caught by testing either side alone.
- (decision) AD: ASSETS ARE DATA AND THE CORE NEVER NAMES ONE. The sim deals in entity and animation identifiers; the renderer maps identifiers to sprites, atlases and hitbox files loaded at runtime. Prevents an art swap from becoming a logic change, which PRD NFR-3.1 requires because everything ships on CC0 placeholders first.
- (decision) AD: CONTENT IS RETIRED BY FLAG, NEVER DELETED. Items, potions, enemies and modifiers carry an active flag; retiring one disables it for new runs while leaving every row that references it intact. Prevents NFR-1.2's failure - an account that owns a removed item, or a historical run that references a removed enemy, becoming unreadable.
- (decision) AD: EVERY RUN EMITS ONE TELEMETRY ENVELOPE, written by the server at run end alongside the reward. Fixed shape: run id, outcome (extracted / died / transformed), depth, environment reached, elapsed ticks, tuning version, device class, modifier. Prevents each feature inventing its own event and makes NFR-1.4's 'changes are observable' true by construction rather than by remembering to instrument.
- (decision) AD: AUTH IS SUPABASE AUTH WITH COOKIE SESSIONS via @supabase/ssr, one browser client and one server client, never shared. Prevents the common Next App Router bug where a server-created client leaks across requests. No account wall before a first run - the brief's instant-play promise - so anonymous play must be supported and later linkable to an account.
- (decision) AD: ENTITLEMENTS ARE SERVER-RESOLVED FOR THIRD-PARTY DISPLAY. A player's own client may render what it believes it owns, but anything another player sees comes from the server's entitlement record. Prevents a hacked client from showing others cosmetics it does not own, which is the only version of that attack that costs real revenue (PRD FR-16.5). Bites in v2/v3; the schema decision is now.

Without it the replay corpus rots invisibly: a bug fix to parry resolution makes every earlier run re-simulate differently and get flagged as forged, confiscating real players' loot. Replay validation only re-simulates runs whose sim version matches the validator.
